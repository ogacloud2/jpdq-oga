### 仕様（明治6年以前の扱い）

- 対象範囲は **明治6年1月1日（1873-01-01）以降**。明治元年〜5年の日付は旧暦（天保暦）のため、年の足し算では
  グレゴリオ暦に換算できない。これらは検証せず、理由コード `pre_gregorian` として**違反扱いで報告**する
  （「検証できない」ことを利用者が識別できるよう、`format` や `not_exist` とは別コードにしている）。
- 元年の西暦は、明治 1868 / 大正 1912 / 昭和 1926 / 平成 1989 / 令和 2019。年の算術は `西暦 = 元年の西暦 + 年 − 1`。
- 元号の期間は、各元号の開始日から次の元号の開始日の前日まで（明治は 1873-01-01 から 1912-07-29）。
- 判定順と理由コード: `format`（読み取れない）→ `pre_gregorian`（明治5年以前）→ `not_exist`（存在しない日、
  令和0年、平年の2月29日を含む）→ `era_boundary`（存在するが元号の期間外。例: 平成31年5月1日、令和元年4月30日）。
- 受け付ける表記: `元年`、半角/全角数字、漢数字（〇〜九、十。99まで）、略号 `R/H/S/T/M`（大文字小文字・全角可）、
  区切り `年月日` または `. / -`、`R060401` 形式。空白は無視する。
- 受け付けない表記: 7桁の元号コード（`5060401` など）。元号の表記ではなくデータ形式であり、日付以外の数値と
  区別できないため。
- テスト: 各元号の初日と前日、元年、閏年（1900年は平年、2000年は閏年）、存在しない月日、
  明治6年〜2060年の全日の往復（`tests/test_wareki.py`）。

### 時点管理（`valid_from` / `valid_to`）

- `valid_from` は含む、`valid_to` は含まない（失効した最初の日）。`NULL` の `valid_from` は「最初に観測したスナップショットより前から有効」、
  `NULL` の `valid_to` は現在も有効。
- スナップショットを取り込むたびに、新しく現れた事実に `valid_from = スナップショット日`、消えた事実に
  `valid_to = スナップショット日` を設定する。**変更は実際の施行日ではなく、それを最初に観測したスナップショットの日付になる**
  （粒度は取り込み頻度に等しい）。同じスナップショットの再適用は何も変えない。
- `as_of` を省略した場合は実行日。`as_of_column` で行ごとの日付（契約日など）を指定できる。

**①現行コード表の構造（実ファイルで確認）**

- シート `R6.1.1現在の団体`（1,794件）と `R6.1.1政令指定都市`（191件、うち20件は前者と重複）。**両シートの和集合（1,965件）が有効なコード**
  （政令指定都市の区は後者にしか無い）。シート名の `R6.1.1` は基準日（2024-01-01）。
- 1行目が見出し（`団体コード | 都道府県名（漢字） | 市区町村名（漢字） | …`）。都道府県自身の行は市区町村名が空。コードは6桁の文字列。

**②改正一覧表の構造（実ファイルで確認）**

- シート `改正一覧表`、見出し4行、データ1,447行、417ブロック。**ブロックは「都道府県名」（E列）が入った行から始まる**。
- 列: 改正前コード（F）・名称（G）／区分（I）／改正後コード（J）・名称（K）／施行年月日（N）。
- 区分: `欠番`・`削除`（改正前コードを廃止）、`新設`（改正後コードを新設）、`〃`（上の行と同じ）、空（コードは変わらない。名称変更・編入合併の存続側）。
- 施行年月日は**ブロックに1つ**だけ書かれ、場所は行によって異なる（廃止行より後ろの新設行に書かれることが多い）。
  表記は3種類: 文字列 `R6.1.1` / `H30.10.1`、日付セル、Excel のシリアル値（例 `41734` ＝ 2014-04-05）。続く行は `〃`。
- コードが整数で入っている行がある（先頭の0が欠落。6桁にゼロ埋めして復元）。名称の前後に空白が入る行がある。
- 検証（実ファイル）: 全ブロックに日付があり、1ブロック内に異なる日付は無い。廃止コード976件のうち現行表に残るものは0。
  新設コード207件のうち現行表に無い7件はいずれも後に廃止（静岡市の区、2005-04-01新設→2024-01-01廃止）。
  日付の範囲は 2005-04-01〜2024-01-01。

**履歴の組み立て（`jpdq_oga.soumu` / `python -m jpdq_oga.cli local-gov-codes-xlsx`）**

- 現行コード → 有効（`valid_to = NULL`）。改正一覧表に `新設` があればその施行日が `valid_from`、なければ `NULL`（窓より前から有効）。
- 改正前コードが `欠番`/`削除` → 現行表に無ければ行を追加し、`valid_to = 施行日`（施行日当日から無効）。名称・都道府県は改正前の値。
- ブロックの日付が無いものは**推測せずスキップ**して警告に出す。現行表と改正一覧表が同じ版でない（廃止コードが現行表にある）場合はエラー。
- 仕様の根拠: 総務省「全国地方公共団体コード仕様」7 — 廃置分合等で欠番になったコードは再利用しない。

**制限（利用者に明示する）**

- **平成17年4月1日より前に廃止されたコードは表に無い**（改正一覧表の対象外）。それ以前の `as_of` では「存在しない」と報告される。
- 名称は現行の名称（過去の名称の履歴は持たない）。
- **現行コード表の基準日は令和6年1月1日**（シート名）。ファイルの更新日（2026-04-01）とは異なり、基準日以降の変更が
  反映されているかは確認できていない。変更があった場合は、新しい版のファイルを総務省から取得するか、
  `local-gov-codes` コマンドでスナップショットを重ねる。
