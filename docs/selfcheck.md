# 自己診断（`jpdq_oga.selfcheck()`）の使い方 — 初心者向け

**所要時間: 5〜10 分。** データは読み書きしません。画面に結果が表示されるだけです。

## これは何をするものか

`jpdq-oga` が、**あなたの Databricks で正しく動くか**を、1 つの命令で確かめます。

| 確かめること | 内容 |
| --- | --- |
| 環境の情報 | Python、Spark、ANSI モード、DQX、Databricks Runtime のバージョンを表示します |
| 8 つのチェック | 答えが分かっている値（正しい法人番号、誤った法人番号、実在しない日付など）で、判定が期待どおりか試します |
| DQX との接続 | YAML から呼ぶための部品を読み込めるか確かめます |

> **いつ使うか**: 初めて使う環境（Free Edition、会社の Databricks、別のクラスター）で、**最初に 1 回**実行します。
> うまく動かないときの原因の切り分けにも使えます。

## 用意するもの

| もの | 説明 |
| --- | --- |
| Databricks のワークスペース | Free Edition でも、会社のワークスペースでも構いません。ログインできる状態にします |
| `jpdq-oga-main.zip`（**最新版**） | GitHub の緑の **Code** ボタン → **Download ZIP** で保存します。展開（解凍）しません。**古い ZIP では `selfcheck` が使えません** |
| ZIP の置き場所（Volume） | まだ無い場合は、[Free Edition の手順書](databricks-free-edition.md)の「5. Volume を作って ZIP をアップロードする」の手順で作ります |

## 手順

### 手順 1. ノートブックを開いて、計算リソースに接続する

1. 左のメニューで **Workspace** をクリックし、自分のフォルダを開きます。
2. 右上の **Create**（作成）→ **Notebook** をクリックして、新しいノートブックを作ります。
   （すでに `databricks_free_edition` ノートブックがある場合は、それを開いても構いません。その場合は、手順 4 に進みます）
3. ノートブックの右上のボタンから、**Serverless**（または使うクラスター）を選び、接続されるまで待ちます。

### 手順 2. インストールする（1 つ目のセル）

ノートブックの最初のセルに、次を貼り付けて、実行します。
実行は、セルの左にある ▶ ボタン、または `Shift + Enter` です。

```python
%pip install databricks-labs-dqx==0.16.0 openpyxl /Volumes/workspace/default/jpdq/jpdq-oga-main.zip
```

- `/Volumes/workspace/default/jpdq/` の部分は、**自分の Volume のパス**に書き換えます
  （Free Edition の手順書どおりに作った場合は、そのままで動きます）。
  パスは、左の **Catalog** で ZIP を開いたときに表示されます。
- 数十秒〜数分かかります。最後に「restart the kernel」のような表示が出ても、正常です。

### 手順 3. Python を再起動する（2 つ目のセル）

新しいセルを追加（セルの下の **＋ Code**）し、次を貼り付けて実行します。

```python
dbutils.library.restartPython()
```

実行後、画面の出力が消えますが、正常です。そのまま次へ進みます。

### 手順 4. 自己診断を実行する（3 つ目のセル）

新しいセルに、次を貼り付けて実行します。

```python
import jpdq_oga

jpdq_oga.selfcheck()
```

| 見るところ | 意味 |
| --- | --- |
| すべての行が `[OK]` | 成功です。この環境で使えます |
| 最後が `True` | 全部期待どおりだったという意味です |
| `[NG]` の行がある、最後が `False` | 期待と違う項目があります。下の表を見てください |

> 上の表示は、手元の PC（Windows）で実行した結果です。Databricks 上では、`Python` の行や `Databricks Runtime` の行の表示が異なります。

## うまくいかないとき

| 表示 | 原因と対処 |
| --- | --- |
| `AttributeError: module 'jpdq_oga' has no attribute 'selfcheck'` | **古い ZIP が入っています。** GitHub から最新の ZIP を取り直し、Volume の古い ZIP を削除して、新しいものをアップロードします。手順 2 のセルを、`%pip install --force-reinstall --no-deps /Volumes/.../jpdq-oga-main.zip` に変えて実行し、手順 3 から続けます |
| `ModuleNotFoundError: No module named 'jpdq_oga'` | 手順 2 または 3 が済んでいません。手順 2 → 3 → 4 の順に、もう一度実行します |
| `No such file or directory: '/Volumes/...'` | ZIP のパスか、ファイル名が違います。**Catalog** で ZIP を開き、表示されたパスに合わせます（`jpdq-oga-main (1).zip` のように名前が変わっていないか確認します） |
| `[NG] Spark のセッションを取得できません` | 計算リソースに接続されていません。手順 1 の 3 で、**Serverless** を選び直します |
| `[NG] DQX のカスタムチェックを読み込めません` | `databricks-labs-dqx` が入っていません。手順 2 のセルを、もう一度実行します |
| `[NG] 法人番号: ...: 期待 ..., 実際 ...` など、行の判定が違う | **環境の問題か、不具合の可能性があります。** 下の「報告のしかた」で知らせてください |

## 報告のしかた

結果が `[NG]` になったとき、または手順が分からなくなったときは、次の 3 つを**そのまま貼って**知らせてください。

1. 自己診断の**出力の全文**（「== 環境 ==」から最後まで）
2. どの手順で止まったか（例:「手順 4 のセルで、赤いエラーが出ました」）と、赤いエラーの**全文**
3. 使っている環境（Free Edition か会社のワークスペースか、Serverless かクラスターか）

自己診断の出力には、データの値は含まれません。そのまま貼っても、業務データが漏れることはありません。
