# Databricks Free Edition で jpdq-oga を試す手順（初心者向け・画面操作つき）

jpdq-oga を、無料の Databricks Free Edition で動かして「日本固有データの検証」を体験する手順です。
**操作を 1 つずつ、押す場所と「押したあとに何が見えれば正しいか」まで書いています。** 所要時間は約 30〜45 分です。

> **この手順書の検証状況**
>
> - **Databricks Free Edition（サーバーレス）の実機で、部 0・部 A・部 B の動作を確認しました（2026-10-15）。**
>   確認は利用者の手で行い、画面で次の結果を確認しています。
>   - Volume の作成、ZIP のアップロード、`%pip install`（Volume の ZIP から）、再起動、`import jpdq_oga` が成功
>   - 部 A: 「問題のない行」が 2 行（id 1・4）、違反が 8 行（id 2・3 が各 4 件）、日本語のメッセージ
>   - 部 B: 基準日の違いで、`9999991` と `9999992` の判定が入れ替わる
>   - 実行環境は Spark Connect（`pyspark.sql.connect.dataframe.DataFrame`）。DQX 0.16.0 の `DQEngine(WorkspaceClient())` も通りました
> - **部 C（日本郵便の実データ）も実機で確認しました（2026-10-16）。**
>   - `utf_ken_all.zip` から `workspace.default.postal_codes` に 120,877 行が書き込まれる
>   - 3 つのチェックの結果: id 1（`100-0001` / 東京都 / 千代田区）は問題なし、id 2（大阪府を組み合わせたもの）は
>     「郵便番号と都道府県が一致しません」、id 3（`000-0000`）は「郵便番号が日本郵便のデータに存在しません」
> - **部 D（総務省の Excel）は、実機では未確認**です（手元の環境では確認済み）。
> - Databricks のコンソールは自動操作をサポートしていないため、実機での確認は利用者の手で行っています。
>   画面の表示名は、バージョンや表示言語によって本書と少し違うことがあります。似た名前のボタンを探してください。
> - うまくいかない場合は「9. つまずいたとき」を見て、解決しなければエラー全文と、どのセルかを知らせてください。
## 0. 用語（初めに）

| 言葉 | 意味 |
| --- | --- |
| ノートブック | Python などのコードを「セル」という四角い枠ごとに書き、1 つずつ実行できる文書 |
| セル | ノートブックの 1 つの枠。コードを書いて実行する単位 |
| Volume（ボリューム） | Databricks 上の「ファイル置き場」。ここに ZIP を置き、ノートブックから読む |
| カタログ / スキーマ | Databricks がデータを整理する 2 段の入れ物（`カタログ.スキーマ.名前`）。Free Edition では通常、カタログ `workspace`・スキーマ `default` が使える |
| Serverless（サーバーレス） | Free Edition で使える計算リソース。ノートブックを実行するには、これに接続する |

## 1. 全体の流れ

| 手順 | やること | 目安 |
| --- | --- | --- |
| 2 | Databricks にログインする | 1 分 |
| 3 | 受け取った 2 つのファイルを PC に保存する | 2 分 |
| 4 | ノートブックを取り込み（Import）、Serverless に接続する | 5 分 |
| 5 | Volume を作り、ZIP をアップロードする | 10 分 |
| 6 | インストールして、セルを上から順に実行する | 10〜15 分 |
| 7 | 結果を確認する | 5 分 |
| 8 | （任意）実データで試す | 15 分 |

## 2. Databricks にログインする

1. ブラウザで、ご自分の Databricks のワークスペースを開き、ログインします。
   - まだ登録していない場合は <https://login.databricks.com/?dbx_source=docs&intent=CE_SIGN_UP>（Free Edition の登録ページ）から
     登録します（メール、Google、Microsoft のいずれか）。
2. ログイン後、左側にメニュー（Workspace、Catalog など）が見えれば OK です。

## 3. 2 つのファイルを PC に保存する

次の 2 つを、PC のわかる場所（デスクトップなど）に保存します。

| ファイル | 入手元 | 注意 |
| --- | --- | --- |
| `jpdq-oga-main.zip` | GitHub の `https://github.com/ogacloud2/jpdq-oga` → 緑の **Code** ボタン → **Download ZIP**。または、手渡しされたファイル | **展開（解凍）しない。** そのまま使います |
| `databricks_free_edition.py` | 同じく GitHub の `examples` フォルダの中。または、手渡しされたファイル | これがノートブックの本体です |

> GitHub のリポジトリが非公開の場合は、ブラウザから見えません。その場合は、渡されたファイルを使ってください。

保存したら、ファイル名が **`jpdq-oga-main.zip`** のままになっているか確認します
（`jpdq-oga-main (1).zip` のように変わっていたら、`(1)` を消して名前を直してください）。

## 4. ノートブックを取り込んで、Serverless に接続する

### 4-1. 取り込む（Import）

1. 左のメニューで **Workspace**（ワークスペース）をクリックします。
2. 自分のフォルダ（`Home`、またはメールアドレスのフォルダ）を開きます。
3. 画面の右上にある **︙**（縦に並んだ 3 つの点）、または **Create**（作成）の横のメニューをクリックし、
   **Import**（インポート）を選びます。
   - 見つからない場合は、フォルダの空いている場所で右クリックしても **Import** が出ることがあります。
4. 開いたダイアログに、`databricks_free_edition.py` を**ドラッグ＆ドロップ**するか、**browse** をクリックして選びます。
5. **Import** ボタンを押します。

**うまくいったかの確認**: Workspace のフォルダの中に `databricks_free_edition` というノートブックが現れます。
クリックして開き、上のほうに「jpdq-oga を Databricks Free Edition で試す」というタイトルが見えれば成功です。

### 4-2. Serverless に接続する

1. ノートブックの**右上**にある、計算リソースを選ぶボタン（**Connect**、または **Serverless** と書かれたもの）をクリックします。
2. **Serverless** を選びます（Free Edition ではこれだけが選べます）。
3. 数十秒待ちます。ボタンの表示が **Serverless**（緑の印つき）などに変われば接続済みです。

## 5. Volume を作って ZIP をアップロードする

ここは、ノートブックのセルと、画面のボタン操作を交互に行います。

### 5-1. セルを実行する方法（以降の共通操作）

- セルの中をクリックして選び、**Shift キーを押しながら Enter** を押すと、そのセルを実行して次のセルに移ります。
- セルの左にある **▶（実行）** ボタンでも実行できます。
- 実行中は、セルの左に小さな回転マークが出ます。**終わるまで次に進まない**でください。
- 最初のセルを実行したときだけ、1 分ほどかかることがあります（計算リソースの起動）。

### 5-2. 現在のカタログとスキーマを確認する（セル「0-1」）

1. ノートブックを上から読み、「**0-1. 今使っているカタログとスキーマを確認する**」の下のコードのセルを実行します。
2. 次のように表示されます。

   ```
   catalog = workspace  / schema = default
   ```

   - **`workspace` と `default`** なら、そのまま進めます。
   - 違う名前が表示された場合は、このあとの `workspace` と `default` を、表示された名前に読み替えてください
     （ノートブックのパスも書き換えます）。

### 5-3. Volume を作る（セル「0-2」）

1. 「**0-2. Volume（ZIP の置き場所）を作る**」の下のセルを実行します。
2. 次のように表示されれば成功です。

   ```
   OK: /Volumes/workspace/default/jpdq ができました（または、すでにありました）
   ```

### 5-4. ZIP をアップロードする（画面操作）

1. 左のメニューで **Catalog**（カタログ）をクリックします。
2. 一覧から **workspace** → **default** の順にクリックします。
3. **Volumes** と書かれた項目（またはタブ）を開き、さきほど作った **`jpdq`** をクリックします。
4. **Upload to this volume**（このボリュームにアップロード）をクリックします。
   - 見つからない場合は、画面右上の **Upload**、または左メニューの **New** → **Add or upload data** →
     **Upload files to a volume** を選び、**Destination volume** で `workspace` → `default` → `jpdq` を指定します。
5. **`jpdq-oga-main.zip`** をドラッグ＆ドロップ（または browse で選択）し、アップロードします。
6. アップロードが終わると、`jpdq` の中に `jpdq-oga-main.zip` が表示されます。

> ZIP のサイズは約 0.25 MB です。数秒で終わります。

### 5-5. ZIP が置かれたことを確認する（セル「0-3」）

1. ノートブックに戻り、「**0-3. ZIP が置かれたか確認する**」の下のセルを実行します。
2. 次のように表示されれば成功です。

   ```
   ['jpdq-oga-main.zip']
   ```

   - **`[]`（空）** の場合: アップロードが終わっていないか、別の場所に置いています。5-4 をやり直してください。

## 6. インストールして、実行する

### 6-1. インストール（セル「0-4」と「0-5」）

1. 「**0-4. インストールする**」の下のセル（`%pip install ...` で始まる）を実行します。
   - 数十秒〜数分かかります。最後に、再起動を促す英語のメッセージが出ても正常です。
   - **赤いエラー**が出た場合は「9. つまずいたとき」を見てください。
2. 次のセル（`dbutils.library.restartPython()`）を実行します。
   - Python が再起動されます。**画面の出力が消えたり、変数が空になったりしますが、正常です。**
   - 再起動後は、ここより前のセルをやり直す必要は**ありません**。次のセルに進みます。

### 6-2. インストールの確認

次のセル（`import jpdq_oga` で始まる）を実行します。次のように表示されれば、インストール成功です。

```

使えるチェック: ['is_consistent_jp_postal_code_and_city', 'is_consistent_jp_postal_code_and_prefecture', ...]
```

## 7. 結果の見方（正しければこうなる）

### 部 A

「問題のない行」には **id が 1 と 4** だけが出ます。違反の表には、**id 2 と id 3 が 4 件ずつ**（計 8 行）出ます。

| id | 内容 | 結果 |
| --- | --- | --- |
| 1 | 国税庁・総務省の公式の例（すべて正しい） | 問題なし |
| 2 | チェックディジット違反、`平成31年5月1日`（実際は令和元年） | 4 つのルールすべてで違反 |
| 3 | 桁数違反、「T」なし、都道府県コード 48、`令和6年2月30日` | 4 つのルールすべてで違反 |
| 4 | すべて NULL | 問題なし（NULL は違反にしません） |

メッセージは、たとえば次のような日本語です。

- `法人番号のチェックディジットが一致しません（入力値: 1234567890123）`
- `元号の期間外の日付です。改元日（昭和64年1月7日／平成31年4月30日 など）を確認してください（入力値: 平成31年5月1日）`
- `存在しない日付です（入力値: 令和6年2月30日）`

「正規表現では通ってしまうが、本パッケージは検出する」例です。

### 部 B

表のメッセージ列が、基準日によって次のように変わります。

| 郵便番号 | 2026-01-01 時点 | 2024-03-31 時点 |
| --- | --- | --- |
| `100-0001`（ハイフン付き）+ 東京都 | 問題なし（NULL） | 問題なし（NULL） |
| `1000001` + 大阪府 | 都道府県が一致しない | 都道府県が一致しない |
| `9999991`（2025-04-01 に新設） | 問題なし（NULL） | 存在しない |
| `9999992`（2024-04-01 に廃止） | 存在しない | 問題なし（NULL） |
| `123-4567` | 存在しない | 存在しない |

「**基準日を変えると、同じデータでも結果が変わる**」ことが確認できれば成功です。

## 8. （任意）実データで試す

### 8-1. 日本郵便の郵便番号（部 C）

> **ノートブックの部 C の最初のセルは、Volume に `utf_ken_all.zip` が無ければ、日本郵便のサイトから自動で取得しようとします。**
> 取得できた場合は、次の 1・2 は不要です。「自動取得できませんでした」と表示された場合だけ、1・2 の手作業を行ってください
> （日本郵便のサイトは、ブラウザ以外からの取得を断ることがあります）。

1. ブラウザで日本郵便の [UTF-8 形式の郵便番号データのページ](https://www.post.japanpost.jp/zipcode/dl/utf-zip.html)
   を開き、**「最新データのダウンロード」**（`utf_ken_all.zip`、約 2MB）をダウンロードします。ZIP は展開しません。
   - 取得できない場合は [ダウンロードの総合ページ](https://www.post.japanpost.jp/zipcode/download.html) から「UTF-8 形式」を探します。
     **必ずブラウザで**取得してください（ブラウザ以外からの取得を拒否することがあります）。
2. 5-4 と同じ方法で、`utf_ken_all.zip` を **同じ Volume（`jpdq`）にアップロード**します。
3. ノートブックの「**C.（任意）日本郵便の実データで…**」以下のセルを上から実行します。
   - 最初の確認セル（`os.listdir`）で、`utf_ken_all.zip` が一覧に出ることを確かめてから進みます。
   - 次のセルは数十秒かかります。`workspace.default.postal_codes に 120877 行を書き込みました` と出れば成功です（行数はデータの更新で少し変わります）。
4. 実在しない `000-0000` の違反と、東京の郵便番号に「大阪府」を組み合わせた違反が出れば成功です。

### 8-2. 総務省の地方公共団体コード（部 D）

> **ノートブックの部 D のセルは、Volume に 2 つの Excel が無ければ、総務省のサイトから自動で取得しようとします**
> （`codes_current.xlsx` と `codes_revisions.xlsx` の名前で保存します）。
> 取得できた場合は、次の 1 は不要です。「自動取得できませんでした」と表示された場合（Free Edition の通信制限や、
> 総務省がファイルを差し替えて URL が変わった場合）だけ、手作業で置いてください。

1. 総務省の [全国地方公共団体コードのページ](https://www.soumu.go.jp/denshijiti/code.html) から、次の 2 つの **Excel** をダウンロードします。
   - 「都道府県コード及び市区町村コード」 → **`codes_current.xlsx`** という名前にして Volume にアップロード
   - 「『都道府県コード及び市区町村コード』の改正一覧表（平成17年4月1日以降）」 → **`codes_revisions.xlsx`** という名前にして Volume にアップロード
   - ファイル名が違う場合は、アップロード前に名前を変えるか、ノートブックのパスを書き換えます。
2. ノートブックの「**D.（任意）総務省の Excel から…**」以下のセルを実行します。

> 平成17年4月1日より前に廃止されたコードは含まれません。現行コード表の基準日は令和6年1月1日です。

## 9. つまずいたとき

| 症状 | 原因と対処 |
| --- | --- |
| セルを実行しても何も起きない・「Connect」のまま | Serverless に接続されていません。右上のボタンから **Serverless** を選び、接続を待ちます |
| 0-2 で `PERMISSION_DENIED` / `not allowed` | カタログ名・スキーマ名が違うか、権限がありません。0-1 で表示された名前に読み替えて、0-2 の `workspace.default` を書き換えます |
| 0-3 で `FileNotFoundError` / `No such file or directory` | Volume が作られていません。0-2 を先に実行してください |
| 0-3 で `[]`（空） | ZIP のアップロードが終わっていません。5-4 をやり直します（展開せず、ZIP のままアップロード） |
| 0-4 で `No such file or directory: /Volumes/...zip` | ZIP の名前が違います。Catalog で `jpdq` を開き、表示されているファイル名に `%pip install` の行を合わせます |
| 0-4 で `Could not find a version` や接続エラー | Free Edition は外部通信が制限されています。時間をおいて再実行します。それでも出る場合は、エラー全文を知らせてください（`databricks-labs-dqx` は PyPI から取得します） |
| `ModuleNotFoundError: No module named 'jpdq_oga'` | 0-4 が成功していないか、0-5（再起動）を実行していません。0-4 → 0-5 の順にもう一度実行します |
| A 部の最初のセルで `NameError: name 'spark' is not defined` | Python の再起動後にセルを実行しているのに接続が切れています。Serverless に接続し直し、0-4 から実行し直します |
| `WorkspaceClient` や認証のエラー | Serverless に接続し直し、0-4 から実行し直します |
| 部 C で `FileNotFoundError ... utf_ken_all.zip`、続けて `TABLE_OR_VIEW_NOT_FOUND ... postal_codes` | Volume に `utf_ken_all.zip` がありません（2 つ目のエラーは、表が作られなかった結果です）。8-1 の 2 をやり直し、`os.listdir` で名前を確認します。`utf_ken_all (1).zip` のように変わっている場合は、名前を直して上げ直します |
| 部 C のチェックのセルで `NameError: name 'yaml' is not defined`（`engine` や `F` でも同様） | 接続が切れて Python の状態が失われています（部 A のセルを実行していない状態）。最新のノートブックでは、このセルだけで実行できます。古いノートブックの場合は、部 A の「`import yaml` から始まるセル」を先に実行します |
| 部 C・D で「自動取得できませんでした」 | Free Edition の通信制限、またはサイト側がブラウザ以外からの取得を断っています。表示された手順どおり、ブラウザで取得して Volume にアップロードし、同じセルをもう一度実行します（8-1・8-2） |
| 部 C で `not a KEN_ALL file` | `utf_ken_all.zip` ではないファイルです。UTF-8 形式の最新データを、ブラウザで取得し直します |
| 「上限」と表示される・計算が止まった | Free Edition の利用量の上限です。リセットされるまで待ちます（データは消えません） |

**知らせていただくときの書き方**（そのまま貼ってください）

1. どのセルか（例:「0-4. インストールする」）
2. 赤く表示されたエラーの**全文**
3. 画面に出ているカタログ名とスキーマ名（0-1 の結果）

## 10. 後片付け

- 作った表を消す: 左の **Catalog** で `workspace.default.postal_codes` などを開き、削除します。
- Volume `jpdq` を消す: 同じ画面で `jpdq` を開き、削除します（中の ZIP も消えます）。

## 11. 自分のデータで使うには

- Free Edition は**非商用・学習用**です。業務データや個人情報を入れないでください。
- DQX のチェック定義（YAML）の書き方は、[examples/dqx_checks.yaml](../examples/dqx_checks.yaml) と
  [examples/dqx_reference_checks.yaml](../examples/dqx_reference_checks.yaml) にあります。
- 各チェックの仕様と制限は [README](../README.md)、出典は [sources.md](sources.md) にあります。
