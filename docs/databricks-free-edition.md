# Databricks Free Edition で jpdq-oga を試す手順（初心者向け）

GitHub から jpdq-oga をダウンロードし、無料の Databricks Free Edition で動かして「日本固有データの検証」を体験する手順です。
プログラミング経験が少なくても、上から順に操作すれば最後まで進めるように書いています。所要時間は約 30〜45 分です。

> **この手順書の検証状況（先にお読みください）**
>
> - ノートブックの **A・B 部は、手元の Spark（通常の Apache Spark 3.5）で実行して期待どおりの結果になることを確認**しています。
>   パッケージ本体は 221 件の自動テストと、日本郵便・総務省の実データで確認済みです。
> - **Databricks Free Edition の実機では、まだ動作確認ができていません。** Free Edition は「サーバーレス（Spark Connect）」
>   だけで動くため、手元の環境と挙動が違う可能性があります。画面の表示名もバージョンで変わります。
>   うまくいかない場合は「9. つまずいたとき」を見て、それでも解決しなければ GitHub の Issue に画面とエラーを貼ってください。

## 0. 先に知っておくこと

| 項目 | 内容 |
| --- | --- |
| Free Edition とは | Databricks の無料版。**非商用**の学習・個人利用向け。サーバーレス計算のみで、使える量に上限があります |
| 外部通信の制限 | 外部への通信は「信頼済みのドメイン」に限られます（[公式](https://docs.databricks.com/aws/en/getting-started/free-edition-limitations)）。そのため GitHub から直接インストールせず、**ブラウザで ZIP を取得して Volume に置く**方法にしています |
| 入れてはいけないデータ | **個人情報・会社の機密データは入れないでください。** この手順は、サンプルデータと公開データだけで進めます |
| 費用 | かかりません（上限を超えると、リセットされるまで計算が止まります。データは消えません） |

## 1. Databricks Free Edition に登録する

1. ブラウザで <https://login.databricks.com/?dbx_source=docs&intent=CE_SIGN_UP> を開きます（Free Edition の登録ページ）。
2. 登録方法（メールアドレス、Google、Microsoft）を選んで登録します。
3. 登録が終わると、自分専用のワークスペース（作業画面）が作られます。左側にメニュー（Workspace、Catalog など）が見えれば完了です。

## 2. GitHub から jpdq-oga をダウンロードする

1. ブラウザで <https://github.com/ogacloud2/jpdq-oga> を開きます。
2. 緑色の **Code** ボタンをクリックし、**Download ZIP** を選びます。
3. `jpdq-oga-main.zip` というファイルがダウンロードされます。**展開（解凍）せず、そのまま**取っておいてください（手順 3 で使います）。
4. ノートブックを取り出すために、ZIP を **別にもう一度、展開**します。展開してできたフォルダの
   `examples` の中にある **`databricks_free_edition.py`** が、後で使うノートブックです（手順 4）。

> GitHub のアカウントは不要です（リポジトリが公開されている場合）。リポジトリが見つからない場合は、
> 非公開になっている可能性があります。公開の案内をした人に確認してください。

## 3. Databricks に ZIP を置く場所（Volume）を作る

Volume は、Databricks 上のファイル置き場です。

1. 左のメニューから **Catalog**（カタログ）を開きます。
2. 一覧から **workspace** を選び、その中の **default** を選びます。
   - カタログ名が `workspace` でない場合は、表示されている自分のカタログ名を使い、後の手順の
     `workspace` を読み替えてください。
3. 右上の **Create**（作成）→ **Volume** を選びます。
4. 名前に **`jpdq`** と入力し、種類は **Managed volume**（マネージド）のまま作成します。
5. 作成した `jpdq` を開き、**Upload to this volume**（このボリュームにアップロード）をクリックします。
   見つからない場合は、左メニューの **New → Add or upload data → Upload files to a volume** からも行えます。
6. 手順 2 でダウンロードした **`jpdq-oga-main.zip`** をドロップ（またはブラウズして選択）し、アップロードします。
7. アップロードされた ZIP の場所は、次のような形になります。

   ```
   /Volumes/workspace/default/jpdq/jpdq-oga-main.zip
   ```

## 4. ノートブックを取り込む

1. 左のメニューから **Workspace** を開き、自分のフォルダ（Home）に移動します。
2. 右上の **︙**（メニュー）または **Create** の近くにある **Import**（インポート）を選びます。
3. 手順 2 で取り出した **`databricks_free_edition.py`** を選んで取り込みます。
4. 取り込まれたノートブックを開きます。

## 5. 実行する

1. ノートブックの右上で、計算リソースとして **Serverless**（サーバーレス）に接続します（Free Edition ではこれだけが選べます）。
2. **上から順に、セルを 1 つずつ実行**します。セルを選んで **Shift + Enter** を押すと、実行して次のセルに進みます。
3. 最初のインストールのセルは、`/Volumes/workspace/default/jpdq/jpdq-oga-main.zip` の場所が手順 3 と
   同じであることを確認してから実行してください（違う場合はこのパスを書き換えます）。
4. 次のセル（`dbutils.library.restartPython()`）を実行すると、Python が再起動されます。**再起動後は、
   ここより前のセルを実行し直す必要はありません。** そのまま次のセルに進んでください。

## 6. 結果の見方

### 部 A: 番号と日付のチェック

4 行のサンプルを検査します。

| id | 内容 | 期待される結果 |
| --- | --- | --- |
| 1 | 国税庁・総務省の公式の例（すべて正しい） | 問題なし |
| 2 | チェックディジット違反、`平成31年5月1日`（実際は令和元年） | 4 つのルールすべてで違反 |
| 3 | 桁数違反、「T」なし、都道府県コード 48、`令和6年2月30日` | 4 つのルールすべてで違反 |
| 4 | すべて NULL | 問題なし（NULL は違反にしません） |

違反の行には、次のような**日本語のメッセージ**が出ます。

- `法人番号のチェックディジットが一致しません（入力値: 1234567890123）`
- `元号の期間外の日付です。改元日（昭和64年1月7日／平成31年4月30日 など）を確認してください（入力値: 平成31年5月1日）`
- `存在しない日付です（入力値: 令和6年2月30日）`

「正規表現では通ってしまうが、本パッケージは検出する」例です。

### 部 B: 参照データと時点指定

小さな郵便番号の表（自分で作ります）を使い、**基準日（`as_of`）を変えると結果が変わる**ことを確認します。

| 郵便番号 | 2026-01-01 時点 | 2024-03-31 時点 |
| --- | --- | --- |
| `100-0001`（ハイフン付き） | 正しい | 正しい |
| `9999991`（2025-04-01 に新設） | 正しい | 存在しない |
| `9999992`（2024-04-01 に廃止） | 存在しない | 正しい |
| `1000001` + 都道府県「大阪府」 | 都道府県が一致しない | 都道府県が一致しない |

## 7. （任意）日本郵便の実データで試す

部 C です。実際の郵便番号データ（約 12 万行）で検査します。

1. ブラウザで日本郵便の [UTF-8 形式の郵便番号データのページ](https://www.post.japanpost.jp/zipcode/dl/utf-zip.html)
   を開き、**「最新データのダウンロード」**（全国一括、`utf_ken_all.zip`、約 2MB）をダウンロードします。
   ZIP は展開しません。ページの構成が変わっている場合は、[ダウンロードの総合ページ](https://www.post.japanpost.jp/zipcode/download.html)
   から「UTF-8 形式」を探してください。
2. 手順 3 と同じ方法で、`utf_ken_all.zip` を **同じ Volume（`jpdq`）にアップロード**します。
3. ノートブックの **部 C** のセルを上から順に実行します。表 `workspace.default.postal_codes` が作られます。
4. 結果に、実在しない郵便番号 `000-0000` の違反と、東京の郵便番号に「大阪府」を組み合わせた違反が出れば成功です。

> ダウンロードできない場合: 日本郵便のサイトは、ブラウザ以外からの取得を拒否することがあります。
> 必ず**ブラウザで**取得してください。

## 8. （任意）総務省の Excel から地方公共団体コードの履歴を作る

部 D です。「合併などで廃止されたコードが、いつまで存在したか」を調べられる表を作ります。

1. 総務省の [全国地方公共団体コードのページ](https://www.soumu.go.jp/denshijiti/code.html) から、次の 2 つの
   **Excel** をダウンロードします。
   - 「都道府県コード及び市区町村コード」 → Volume に **`codes_current.xlsx`** という名前でアップロード
   - 「『都道府県コード及び市区町村コード』の改正一覧表（平成17年4月1日以降）」 → **`codes_revisions.xlsx`** という名前でアップロード
   - ダウンロード後のファイル名が違う場合は、アップロード時に名前を付け替えるか、ノートブックのパスを書き換えます。
2. ノートブックの **部 D** のセルを実行します。表 `workspace.default.local_gov_codes` が作られ、廃止されたコードが表示されます。

> 注意: 平成17年4月1日より前に廃止されたコードは、この表に含まれません。現行コード表の基準日は令和6年1月1日です。

## 9. つまずいたとき

| 症状 | 原因と対処 |
| --- | --- |
| インストールのセルで `No such file or directory: /Volumes/...zip` | ZIP の場所が違います。Catalog で Volume を開き、ZIP をクリックして表示される**パスをコピー**し、`%pip install` の行に貼り直します。ZIP を展開してアップロードしていないかも確認してください |
| インストールのセルで `Could not find a version` や接続エラー | Free Edition は外部通信が制限されています。時間をおいて再実行してください。それでも出る場合は Issue に報告してください（`databricks-labs-dqx` は PyPI から取得します） |
| `ModuleNotFoundError: No module named 'jpdq_oga'` | `dbutils.library.restartPython()` の前にインストールのセルが成功していない可能性があります。インストールのセルをもう一度実行し、続けて再起動のセルを実行してください |
| `Permission denied` / `PERMISSION_DENIED`（Volume や表） | カタログ名・スキーマ名が違うか、権限がありません。Catalog で自分が使えるカタログ（通常は `workspace`）とスキーマ（`default`）を確認し、ノートブックの名前を合わせます |
| `WorkspaceClient` や認証のエラー | ノートブックの `DQEngine(WorkspaceClient())` で出ます。サーバーレスに接続されているか確認し、接続し直して最初から実行してください |
| `unsupported language` | チェックの `lang` は `ja` か `en` だけです |
| 部 C で `not a KEN_ALL file` | `utf_ken_all.zip` ではないファイルを置いています。UTF-8 形式の最新データを、ブラウザで取得し直してください |
| 計算が止まった・「上限」と表示される | Free Edition の利用量の上限です。リセットされるまで待ってください（データは消えません） |

エラーメッセージの**全文**と、どのセルで出たかを控えておくと、原因を調べやすくなります。

## 10. 後片付け

- 作った表を消す場合: 左の **Catalog** で `workspace.default.postal_codes` などを開き、削除します。
- Volume `jpdq` と中のファイルも、同じ画面から削除できます。
- Free Edition のワークスペース自体は、そのまま残しても費用はかかりません。

## 11. 自分のデータで使うには

実データを扱う場合は、次の点にご注意ください（Free Edition は非商用・学習用です）。

- 業務データや個人情報を Free Edition に入れないでください。
- DQX のチェック定義（YAML）の書き方は、[examples/dqx_checks.yaml](../examples/dqx_checks.yaml) と
  [examples/dqx_reference_checks.yaml](../examples/dqx_reference_checks.yaml) にあります。
- 各チェックの仕様と制限は [README](../README.md)、出典は [sources.md](sources.md) にあります。
